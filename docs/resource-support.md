# Resource support

What works today. Anything not listed is **not supported**. Labels: **Discovery** = read by `provider-aws` (tested against an in-memory fake AWS; not yet exercised against a real account), **Generation** = produced by `generator-cdk` (compiled and synthesized with `aws-cdk-lib` 2.275 in the test suite).

| Service / type                                                                | Discovery                                | Generation                       | Notes                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------------------------------- | ---------------------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Lambda `AWS::Lambda::Function` (zip)                                          | yes                                      | L2 `Function`                    | Code and environment **values** are never collected; code comes from CloudFormation parameters, env values from parameters. Layers, ephemeral storage, tracing, architecture, event source mappings (SQS, DynamoDB streams) supported. VPC, file systems, DLQ config, KMS key and container images are recorded and listed as unresolved. |
| API Gateway v2 HTTP API `AWS::ApiGatewayV2::Api`                              | yes                                      | L2 `HttpApi`                     | Lambda proxy integrations, CORS, `$default` and named stages. **Routes with an authorizer are not created** (they would become unauthenticated); they are listed as unresolved. WebSocket APIs and REST APIs are not supported.                                                                                                           |
| DynamoDB `AWS::DynamoDB::Table`                                               | yes                                      | L2 `Table`                       | Keys, GSIs/LSIs, billing mode, streams, PITR, TTL, deletion protection, SSE, table class. `RETAIN` removal policy. No names set.                                                                                                                                                                                                          |
| SQS `AWS::SQS::Queue`                                                         | yes                                      | L2 `Queue`                       | Timeouts, retention, FIFO, SSE, redrive/DLQ. KMS keys unresolved. `RETAIN`.                                                                                                                                                                                                                                                               |
| EventBridge bus and rules                                                     | yes                                      | L2 `EventBus` / `Rule`           | Patterns, schedules, state, Lambda and SQS targets. Input transformers, DLQ and retry settings on targets are unresolved.                                                                                                                                                                                                                 |
| S3 `AWS::S3::Bucket`                                                          | yes (metadata only)                      | L2 `Bucket`                      | Versioning, encryption, public access block, Lambda notifications (only on buckets the plan owns). Objects are never read.                                                                                                                                                                                                                |
| IAM `AWS::IAM::Role`                                                          | yes (roles used by discovered functions) | L2 `Role` (L1 for complex trust) | Inline policies preserved verbatim with recreated ARNs rewired; managed policies by ARN. Permissions boundaries unresolved.                                                                                                                                                                                                               |
| Everything else (VPC, RDS, ECS/EKS, Cognito, Step Functions, CloudFront, ...) | no                                       | no                               | Excluded explicitly with an `unsupported-resource-type` entry; never silently dropped.                                                                                                                                                                                                                                                    |

Relationship kinds: `routes-to`, `triggers`, `dead-letters-to`, `assumes-role`, `rule-on-bus`, `targets`, `notifies`, `same-stack` (derived from CloudFormation stack tags), and `possible-access` (hypothesis only).

Strategies: `balanced` works. `faithful` (L1-only) and `modernized` are rejected with an explicit message. Ownership: `recreate` and `reference` are generated; `adopt` is planning-only advice.
